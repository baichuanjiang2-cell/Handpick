# 录屏移除 · 交接说明

> 这不是变更日志（本项目[不另开变更日志](改动说明规范.md)）。这是一份**一次性交接快照**：写给下一个接手的人或 AI，说明现在仓库处于什么状态、为什么是这样、哪些坑已经踩过、还剩什么没做。历史以 git 记录与 [ADR 0015](adr/0015-recorder-removal.md) 为准。

**一句话**：软件里所有屏幕录制能力已被彻底删除；随后修好了两处让 `pnpm run start` 起不来的问题，软件已能正常启动；改动全部留在工作区，**未提交 git、未打包**。

## 1. 决策是怎么定下来的

用 `grill-with-docs` 做了两轮拷问，用户逐条确认后回「理解一致，开工」。确认的结论：

| # | 决定 |
| --- | --- |
| 1 | 软件从此**没有任何录视频能力**。「录屏」入口实际跑的就是原「超级录屏」引擎，另有隐藏的「经典录屏」兼容模式，两者共享悬浮条与大部分设置，无法只删一半 —— 整块拿掉 |
| 2 | 界面上不留占位、不留禁用态、不留「功能已移除」提示 |
| 3 | 用户个人文件夹里的视频文件**一律不碰、也不扫描**；软件自身的配置残留由启动时迁移清理 |
| 4 | 对外文案静默去掉「录屏」，标语改为「识屏 · 剪贴板历史 · 翻译」，不写替代词、不写「已移除」 |
| 5 | 文档 / README / 术语表全部改干净；`docs/adr/0014-*` 整篇删除；另建 ADR 0015 记录决定与停用术语 |
| 6 | 共享代码只收窄：`save_file_path` / `ok_save` 保留、去掉 `isVideo` 分支；截图 / 贴图保存、高级图片编辑等无关功能必须不受影响 |
| 7 | 打包资源一并砍掉：ffmpeg 下载、deb/rpm 的 ffmpeg 依赖、`gifenc` / `mediabunny` 及锁文件条目 |
| 8 | 8 个语言包按项目规矩清理录屏词条；不跑 `tool.js -u`（会重排 id） |
| 9 | 收尾跑格式化 / 类型检查 / lint；不写新测试、不提交 git、不打包 |

### 阶段 B：修好 `Error: Electron uninstall`

原因是我为跑类型检查用了 `pnpm install --ignore-scripts`，跳过 Electron 的安装脚本（装依赖时负责下载软件主程序的一段程序），`path.txt` 与 `dist/electron.exe` 缺失。修复：从本机缓存 `electron-v44.3.0-win32-x64.zip` 离线解压（sha256 与 `checksums.json` 一致），补写 `path.txt`；顺带重新 `pnpm run build` 刷新 `out/`。

### 阶段 C：修好主进程 `非法的翻译资源文件名: ./ignore.json`

**与录屏删除无关，是仓库既有缺陷**（`git show HEAD:lib/translate/translate.ts` 可验证，该文件此前从未被改动）。`readJson(name)` 用「只允许纯文件名」的正则校验整个 `name`，但所有调用都带 `./` 前缀，模块顶层一加载就抛错。之前没暴露只是因为软件主程序没装好、主进程从未启动。

修复只在 `lib/translate/translate.ts`：`const base = path.basename(name)`，校验与读取都用 `base`，原有安全限制不变。

## 4. 踩过的坑（接手前请先看）

1. **`pnpm install` 不要加 `--ignore-scripts`**，否则 Electron 二进制不落地，`pnpm run start` 报 `Electron uninstall`。
2. 若已踩坑，本机缓存通常在 `%LOCALAPPDATA%/electron/Cache/<hash>/electron-v<版本>-win32-x64.zip`。`node node_modules/electron/install.js` 在受限环境可能被终止，可直接用 zipfile 解压到 `node_modules/electron/dist/` 并写 `path.txt`（内容 `electron.exe`）。
3. **`pnpm run start` 是 `electron-vite preview`，每次都会先 build**，不是单纯启动。build 会清空 `out/renderer/assets`。
4. 工具环境设了 `ELECTRON_RUN_AS_NODE=1`，直接跑 `electron.exe` 会变成 Node 模式、`require("electron")` 返回路径字符串，产生误导性的 `Cannot read properties of undefined (reading 'getPath')`。验证启动要 `env -u ELECTRON_RUN_AS_NODE`。
5. `core.autocrlf=true` 且仓库文件是 CRLF，但 Biome 默认 LF。跑完 `pnpm run format` 会把 `src/` 全量转成 LF，`git status` 多出约 32 个**无内容 diff** 的 M 条目 —— 这是换行差异，不是改动。要 lint 通过就得保持 LF 状态。
6. 第三方 `xtimelog` 的类型错误是既有的，别当成回归。
7. 详见 [本地启动与排障](develop/本地启动与排障.md)。
