# 剪贴板历史独立窗口：任务栏入口改为面板本身

> 本决定**部分取代** [ADR 0002](0002-main-window-model.md)。0002 关于「主页面窗口关闭即隐藏、强制单窗口」的部分作废，其余（补 `window-all-closed` 兜底）保留。

## 背景

ADR 0002 让**主页面**（`editor.html`，即搜索 / 翻译编辑器）常驻任务栏，并把剪贴板历史做成它内部的一个 `WebContentsView` 标签页。

这个模型有一个没有被意识到的后果：**任务栏图标绑定的是「窗口」，不是「标签页」。**

于是需求「剪贴板面板同时可以从托盘和任务栏入口打开」中，托盘那半条实现了，任务栏那半条**根本无法实现**——点任务栏图标只会把主窗口显示出来，窗口停在默认的 home 态，也就是那个搜索编辑器。用户在实机上点开看到的正是这个，与预期完全不符。

## 决定

**剪贴板历史改为独立窗口**，它自己就是任务栏入口；**主页面改回按需打开**。

具体：

1. 新增 `clipHistoryWindow`，加载 `clipboardHistory.html`，程序启动即以最小化状态创建，承担任务栏入口的角色。
2. 托盘菜单「剪贴板历史」、首次运行通知、任务栏按钮，三者都指向这一个窗口。
3. 面板窗口**关闭即最小化**（不是隐藏），这样任务栏图标始终在，随时点得开。真正退出走托盘「退出」。
4. `createMainWindow` 回退到上游行为：`主页面.复用` 逻辑恢复、托盘「复用主页面」菜单项恢复、关闭即销毁。
5. 移除主页面里的剪贴板标签页相关代码：`createBrowser` 的 `clipboardHistory.html` 分支、`browserFocus` IPC 通道、`ensureMainWindow()`。

## Considered Options

- **保留标签页，只在启动时把当前标签页切到剪贴板** —— 放弃：窗口外壳仍是编辑器（顶部有编辑器工具栏），且用户一旦新建/关闭标签页就会退回搜索编辑器，仍然「不是剪贴板」。
- **面板做成托盘旁的弹出小窗** —— 放弃：更贴近专业剪贴板工具，但需要自绘无边框窗口并处理失焦收起，改动与风险都明显更大。留作后续可选。
- **主搜索页也继续常驻任务栏** —— 放弃：任务栏会出现两个图标，且用户明确表示主搜索页不需要常驻。

## Consequences

- 任务栏入口与用户预期一致：点开就是剪贴板面板。
- 主搜索编辑器恢复上游的按需行为，OCR / 搜索 / 翻译不受影响；关闭后不再占用任务栏。
- 面板窗口的尺寸单独用 `剪贴板历史.窗口大小` 记录（默认 `420 × 640`）。
- 程序启动时创建的是面板窗口而非主窗口，启动开销与 ADR 0002 时期相当。
- 「所有窗口关闭即退出」的兜底仍由 `window-all-closed` 空处理器承担。

## 附带修复：窗口尺寸漂移

记录窗口尺寸时发现一个独立缺陷：**Electron 读回的窗口尺寸总比创建时多几像素**（实测 +1 ~ +4，Windows 会把窗口吸附到自己的网格）。原样 `getBounds()` → `store.set` → 下次 `new BrowserWindow` 的循环会让窗口**每开关一次就长大一点**。上游的 `主页面大小` 一直有这个问题。

处理方式：加**滞回阈值** `WIN_SIZE_EPS = 10`——只有尺寸变化超过 10px 才写回 store。实测 `916 × 657` 的主窗口与 `420 × 640` 的面板在连续三轮启动中数值完全不变，同时用户真正拖动窗口仍会被记录。

曾考虑把尺寸取整到 10px 网格，但实测误差最大到 +4，与 `Math.round` 的 5px 判定阈值余量太紧，可能失效，故弃用。
