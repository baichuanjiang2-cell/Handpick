# 控制中心与设置页改用视觉对齐三规则

Status: accepted

**控制中心**壳与**设置**页（含独立设置窗口）放弃"盒子边线对齐"，改用三条**视觉对齐**规则。范围不含截屏、贴图、屏幕翻译、录屏等**覆盖层**，它们的排版一条不动。

1. **间距刻度**：间距与内边距只用 `4 / 8 / 12 / 16 / 24 / 32 / 40`，40 以上取 8 的倍数。刻度只管间距，**不管元素尺寸**——52px 页头、34px 控件簇、232px 侧栏、13.5px 基准字号这些已经批准的尺寸保持不变。落在刻度外的固定值按最近档位校正：`22→24`、`28→32`、`2→4`、`150→160`。**负向光学偏移豁免**（如 `outline-offset: -1px`），它不是间距而是描边收缩量。
2. **列对齐**：设置正文收进 820px 列；每行设置是"左名称 / 右控件"两列，控件列定宽 360px，使所有控件左边缘落在同一条竖线上；正文列窄到 640px 以下时两列改上下堆叠。21 条 `blockSetting` 控件成为**宽控件行**。`全局.主题` 保留原结构，只在内部加一层三列子网格（标签 + 浅色值 + 深色值）。快捷键图标从控件侧移到名称侧。**关于页**收进 820px 列内左对齐，标志与软件名在列内居中。控制中心记录行预留固定宽度的操作列，动作按钮左边缘恒定于同一条 x。
3. **光学居中**：图标、文字、符号按**字形**视觉重量居中，允许 ±1px，而不是按外框（bounding box）几何居中。

独立设置窗口默认尺寸随之从 900×700 改为 1060×700（最小宽 600 不变），它的窗控簇从 28px 升为 34px。

## Considered Options

- **继续按盒子对齐** — 放弃：图标的 svg 外框含留白，按外框居中后眼睛看到的重心偏上偏左；两列各按自己盒子排，控件左边缘参差不齐。
- **把刻度也管到元素尺寸上** — 放弃：尺寸由可读性和点击区决定，硬套刻度等于重排所有已批准的样子。
- **控件列宽随内容自适应** — 放弃：每行控件宽度不同，左边缘就成了 N 条竖线，扫视时无法用一条垂直线从上往下读。
- **连覆盖层一起改** — 放弃：截屏、贴图是叠在他人内容上的工具面，重排版有干扰取色的风险，本轮只做壳与设置。

## Consequences

- 每条改动收尾要跑两项机检，不靠肉眼：① 扫描**实际加载**的 CSS 与两个页面 TS 内联样式里的所有间距值，断言全部落在刻度上；② 用调试协议（CDP）读每一行名称与控件的 `boundingBox`，断言左边缘 x 各自单值、**宽控件行**的控件 x 与名称 x 相同。
- 共用的 `src/renderer/lib/ui.ts` 与 `src/renderer/css/css.css` 里属于范围外窗口的旧默认值（如 28px 窗控、`gap: 6px`）**保留不改**，改由 CSS 变量（`--win-ctl-size` 等）与页面内局部覆盖让**控制中心**和**设置**落到刻度上，避免动到录屏、高级编辑等窗口。
- 独立设置窗口的 1060 只是**新配置文件的默认值**；老用户恢复的是自己记住的尺寸，看不到这个变化。
- 对 [ADR 0010](./0010-control-center-typography-and-appearance.md) 的范围澄清：那里写的"其它窗口保持 28px"仍然成立，但**独立设置窗口**从本版起属于 34px 一族。
- 光学居中的 ±1px 与"40 以上取 8 的倍数"这两条是我补的量化口径，不是从既有约定推出来的；如果后续要严格执行，需要重新确认。
