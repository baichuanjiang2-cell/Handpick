# 0009. 入口统一：控制中心与托盘瘦身

日期：2026-10-18

## 状态

已采纳。**部分修订 [ADR 0004](0004-clipboard-history-standalone-window.md) 的结论**：0004 说「任务栏按钮 = 剪贴板面板」，本 ADR 将该窗口升级更名为**控制中心**并赋予门面职责；0004 的"独立窗口、任务栏按钮绑定它"的核心结论不变。

## 背景

用户反馈打开软件的方式不协调：任务栏按钮开剪贴板面板、托盘左键直接进截屏框选、托盘右键弹出 20 项的系统原生文字菜单——三种入口三种行为三种长相，且软件大部分功能藏在那个原生菜单里，操作不顺手。

## 决策

1. **控制中心**：原剪贴板面板升级为**整个软件的壳窗口**（参考 Gleanx 的布局：左侧边栏导航 + 顶栏 + 主内容区）。侧边栏承载可嵌页面栏目（剪贴板历史=默认页、翻译、AI 识图、设置）与**工具组**（23 个全局动作的折叠分组，默认展开）；顶栏是快路径（快速截屏、自动识别、回到剪贴板）+ 纸墨三窗控（金=最小化、空心墨点=最大化、朱砂=关闭）。主页面（编辑器）与帮助保持独立窗口；截屏/贴图/屏幕翻译/录屏提示等覆盖层不进壳，从工具组触发出去。布局学参考图，配色保持纸墨（墨绿升格主操作色，金/朱砂语义不动）。
2. **托盘瘦身**：右键菜单从 20 项瘦身为 4 项（打开控制中心 / 快速截屏 / 暂停记录 / 退出）；左键保留「快速截屏」直接框选。
3. **一张动作表**：新增 `appAction` IPC 通道 + `appActions` 动作表（主进程唯一派发入口），托盘与功能清单都只派发这组动作，两边不会各写一份而漏功能。动作派发同步返回开关项最新状态，渲染端不读旧值。
4. **零丢失核对**：旧 20 项菜单的每一项在功能清单中有对应条目（含 dev 模式专属的「退出开发者模式」）。

## 替代方案

- 新建独立「控制中心」窗口（三个窗口更碎，否决）
- 只重画托盘菜单不动行为（治不了"入口不协调"，否决）

## 形态修订（同日）

初版决策是"小面板 + 功能清单弹层"；用户随后要求"点任务栏图标显示整个软件"，形态重设计为上述壳窗口。**尺寸档位**设置保留，含义改为"打开控制中心时的大小"。「功能清单」词条随之改写为「**工具组**」（侧边栏折叠分组）。

## 后果

- 用户点任务栏图标即可到达任何功能，心智模型：**点任务栏图标 = 打开这个软件，什么都能干**。
- 托盘长菜单（原生样式）不再承载功能，UI 观感统一到纸墨语言。
- 「剪贴板面板」成为历史术语，历史文档中指升级前的形态。
