# 剪贴板面板：内容编辑、图片预览、液态毛玻璃与尺寸档位

> 承接 [ADR 0005](0005-clipboard-panel-delivery-and-polish.md)。0005 解决「怎么交付、怎么用」，本决定解决后续提出的四件事：记录要能改、图片要能放大看、面板要有液态毛玻璃、点任务栏唤出的尺寸要可选。

## 背景

面板跑起来之后暴露的四处不足：

1. **记录只能整条复制或删掉，改不了内容。** 复制来的文本常常带多余的前后缀，或者只错一个字，用户只能删掉重新复制一遍。
2. **图片只有 200px 缩略图可看。** 取图通道 `clipHistoryThumb` 就是按 200px 缩放的，没有看原图的入口。
3. **面板是实心的**，与「液态毛玻璃」的观感不符。
4. **唤出尺寸不可控。** 只有「记住上次拖动的结果」一种行为，没法要求「点任务栏就铺成半屏」。

## 决定

### 1. 文本与文件记录可就地编辑，图片不可

- **可编辑范围**：文本记录改正文，文件记录改路径列表（一行一条）。**图片不提供内容编辑**——真要改图得接 `photoEditor`，那是另一个量级的事，本决定不做。
- **交互**：卡片**内联**编辑。点卡片上的「编辑」图标，内容块就地换成 `textarea`，操作区换成「保存 / 取消」。不弹窗、不开新窗口——面板本身就是任务栏窗口，多开窗口会多出一个任务栏按钮。
- **重算 hash**：`hash` 同时承担「新内容去重」与「复制回剪贴板时的回声抑制」，所以内容一改必须重算，否则同一个内容会被当成新内容再记一遍。
- **撞车即合并**：改完的内容若与**另一条**已有记录完全相同，删掉另一条、保留被编辑的这条，并把对方的**固定**状态并入。理由：`byHash` 是 `hash → 单条` 的索引，允许重复会让去重语义整个塌掉；而「两条一模一样的内容」对用户没有任何价值。
- **空内容拒绝保存**：清空文本或清空路径列表时返回 `false`，面板留在编辑态让用户改回来，不留下一条空记录。
- **回收站不可编辑**：`editText` / `editFiles` 对 `deleted` 的条目直接拒绝。

### 2. 图片放大走面板内的 `<dialog>` 弹层，取原图

- 眼睛图标**常驻**在图片卡片右上角（与复制 / 固定 / 删除同排），缩略图本身**不**整块可点——面板里图标排本来就是常驻的，单独给缩略图加点击区反而容易误触。
- 弹层用原生 `<dialog>` + `showModal()`，`::backdrop` 已经带毛玻璃，Esc 与点遮罩都能关。
- **取原图**而不是缩略图：新增 `clipHistoryFull` 通道，直接复用 `ClipboardHistory.getImage()`。它与 `clipHistoryThumb` 一样是同步 IPC——面板的 `clipHistoryGet` 本来就是同步返回整张列表，同步取图与既有模式一致。
- **眼睛与编辑互斥**：图片卡片只出现眼睛，文本 / 文件卡片只出现编辑。避免在同一排里塞一个点了没反应的按钮。

### 3. 液态毛玻璃交给系统材质（Windows 亚克力）

- 面板窗口加 `backgroundMaterial: "acrylic"`，窗口底色改成全透明 `#00000000`。
- 页面 `body` 加 `glass` 类，底色改成 `color-mix(in srgb, var(--bg) var(--alpha), transparent)`，即**复用「样式 → 毛玻璃效果」里的不透明度**，不给面板单开设置项。
- **为什么必须是系统材质**：Electron 官方在「自定义窗口样式」里明确写了 CSS `blur()` 滤镜只作用于窗口自己的网页内容，**无法模糊窗口下方的桌面**。纯 CSS 做不出真模糊，只能做出一层半透明色。
- **为什么保留原生边框**：无边框 + 自绘标题栏才能拿到完整的圆角玻璃外观，但那要自己实现拖拽、关闭、缩放，改动与风险都大得多，留作后续可选。
- **降级是零成本的**：材质不生效时（非 Windows、Win10、系统「透明效果」关闭），页面那层半透明叠在**不透明的窗口底色**上，结果仍等于改动前的实心外观，所以不需要额外的降级分支。
- 顺手修掉一个既有缺陷：设置页写 `--alpha` 用的是 `String(v)`（`"0.4"`），而 `initStyle` 用的是 `${v * 100}%`（`"40%"`）。`color-mix` 只认百分比，`"0.4"` 不合法，所以以前改完不透明度要重开页面才生效。

### 4. 唤出尺寸做成四档，`100%` 是最大化而不是全屏

- 新增设置项 `剪贴板历史.窗口尺寸`：`默认` / `50%` / `75%` / `100%`。
- **百分比以光标所在显示器的工作区为基准**，不是整个屏幕——用工作区才不会压住任务栏。非「默认」档时窗口居中于该工作区。
- **`100%` 走 `maximize()`**，不是 `setFullScreen(true)`。全屏会盖住任务栏，而面板不该盖住任务栏。
- **`默认` 档保持原行为**：沿用 `窗口大小` 记住的尺寸；从百分比档切回「默认」时，`applyClipHistorySize` 会把窗口恢复成记住的尺寸（否则它会一直停在档位尺寸上）。
- **施加时机**：`win.on("restore")` + `showClipHistoryWindow()`。前者是必须的——点任务栏图标是 Windows 在还原窗口，它会沿用最小化前的尺寸，档位不重新施加就不会生效。
- **非「默认」档不记录拖动结果**：档位决定尺寸，记下来只会把「默认」档该用的尺寸污染掉。位置同理。

## Considered Options

- **编辑放弹窗 / 独立窗口** —— 放弃：内联改动最小、最直观，也不新增窗口。
- **图片放大新开一个窗口** —— 放弃：面板本身就是任务栏窗口，新窗口会多一个任务栏按钮，还要单独管位置与生命周期。
- **图片放大直接开 `photoEditor`** —— 放弃：那是「编辑」语义的重型窗口（`maximize()` + 全套工具），只为看一眼原图太重；留给「以后真要改图」的场景。
- **纯 CSS 半透明冒充毛玻璃** —— 放弃：做不出模糊，只是把面板调成半透明，桌面透出来是清晰的。
- **无边框窗口 + 自绘标题栏** —— 放弃：最接近「液态玻璃」，但要自己实现拖拽、关闭、缩放，风险明显更大。留作后续可选。
- **`100%` 用全屏** —— 放弃：会盖住任务栏，与「面板」的定位冲突。
- **百分比以整个屏幕为基准** —— 放弃：同上，会压住任务栏。
- **非「默认」档也记录拖动尺寸** —— 放弃：会把「默认」档的尺寸污染成档位尺寸，切回「默认」就再也回不到用户原来的大小。

## Consequences

- 文本 / 文件记录可以改内容，改完自动处理去重与回声抑制；图片记录多了一个「看一眼原图」的入口。
- 面板在支持系统材质的环境下是系统绘制的亚克力毛玻璃；不支持时外观与改动前一致，不会变成一块奇怪的半透明板。
- 点任务栏唤出面板时，尺寸由设置项决定；「默认」档仍然是「记住你上次调的大小」。
- **实测发现**：本机（Windows 11 23H2 / build 22631）的「透明效果」是**关闭**的（`HKCU\...\Themes\Personalize\EnableTransparency = 0`），此时 `acrylic` 会退化成一层不透明的浅色，看不出模糊。**要看到真正的液态毛玻璃，需要在「设置 → 个性化 → 颜色 → 透明效果」里打开它。** 这条是用探针实测出来的，不是推断：同一组窗口分别用 `acrylic` / `tabbed` / `mica` / `none`，前三个在跨越黑白边界的底图上都得到「均值偏高、标准差 0」（即完全不透），只有 `none` 保留了底图对比度（168±82）。
- 面板的毛玻璃强度跟随「样式 → 毛玻璃效果 → 不透明度」（默认 0.4）。系统材质不生效时把它调高，面板会更接近实心。
