# 剪贴板历史的落盘格式与加密方案

剪贴板历史需要落盘保留，且内容（尤其截图）敏感。

决定：文本与元数据写入 JSON 索引，图片以独立 PNG 文件存储；两者整体用一把随机 **AES-256-GCM** 密钥加密，该密钥本身交给 Electron `safeStorage` 保管（底层为 Windows DPAPI / macOS Keychain / Linux keyring）。

理由：逐条调用 `safeStorage` 加解密开销大、且不利于流式处理图片；用一把对称密钥加密数据、只把密钥交给系统保管，兼顾性能与跨平台一致性。

## Considered Options

- **直接用 `safeStorage` 加密每一条内容** —— 放弃：每条都要加解密，图片需转成字符串，开销大。
- **不加密，明文落盘** —— 放弃：用户明确要求加密。
- **用用户主密码派生密钥** —— 放弃：威胁模型只要求「不明文落盘」，主密码会牺牲免密体验。

## Consequences

- 密钥绑定本机，存储目录若被同步到别的电脑将**无法解密**。
- `safeStorage` 不可用时（如没有 keyring 的 Linux）降级为**明文存储**，必须在设置页显著提示。
- 搜索与预览需要先在内存中解密，启动时会有一次性解密开销。
