# 剪贴板面板的液态玻璃：自采集桌面 + 真折射

> **本决定取代 [ADR 0006](0006-clipboard-panel-edit-preview-glass-size.md) 的第 3 条**（「液态毛玻璃交给系统材质」）。0006 的其余三条（内容编辑、图片预览、尺寸档位）继续有效。
>
> 设计过程与市面做法的调研见 [`docs/液态玻璃开发方案.md`](../液态玻璃开发方案.md)。

## 背景

0006 给面板加了 `backgroundMaterial: "acrylic"`，让 Windows 用 DWM 在窗口后面画一层亚克力。这条路有硬伤：

1. **要用户先打开系统开关**。本机实测（Win11 23H2 / build 22631）`EnableTransparency = 0`，`acrylic` 直接退化成一层不透明的浅色，看不出模糊。要求用户去改系统设置才能看到效果，对「面板好不好看」这件事来说是错的。
2. **观感不对**。系统材质只是「背景变糊」，没有液态玻璃最有辨识度的两件事：**边缘的折射**与**前景的光学层**。
3. **面板里原有的 `backdrop-filter: var(--blur)` 一直在空转**。它模糊的是「页面内部已经画好的内容」，而面板页面底下只有一层纯色，等于什么都没做。

同时确认了一条结构性事实：**CSS 的 `backdrop-filter` 采样不到桌面**。它只能采样页面内部已绘制的内容，桌面是 DWM 在 Chromium 的合成器之外画的，不在页面绘制树里。旁证：全世界所有 Electron 应用做桌面毛玻璃都走 `vibrancy` / `backgroundMaterial`；如果 CSS 可行，没人会需要那两个原生 API。WebKit bug 245510 / Mozilla bug 1961378 挂了多年未解。

于是只剩一条路：**自己把桌面截进页面**。搬进来之后，`backdrop-filter` 才第一次真的有东西可弯。

## 决定

### 1. 背景由主进程截图搬进页面，分三层

```
.lg-desk   主进程截下来的桌面图，按屏幕坐标摆正
.lg-tint   一层色纱，厚度跟随「样式 → 毛玻璃效果 → 不透明度」
.lg-lens   对上面两层做模糊与折射（backdrop-filter 引 SVG 滤镜）
```

三层都用**负 z-index** 压在内容下面。负 z-index 的绘制顺序是「栈上下文背景之后、正常流内容之前」，正好卡在画布底色与卡片文字之间——所以内容不需要任何包裹层，也不用给面板加新的 DOM 结构。

背景图交给 `background-image` + `background-size: 100% 100%`，不用 `<canvas>`：少一次每帧 `drawImage` 的拷贝，而且**窗口移动时只改 `left/top`、不重绘**。

### 2. 桌面图按「显示器坐标 − 内容区坐标」摆正，位置变化只推几何

图是屏幕对齐的整块显示器截图，而面板视口只看到屏幕的一部分，所以图要往左上偏移「显示器原点 − 内容区原点」。

- 坐标用**内容区**（`getContentBounds()`）而不是外框（`getBounds()`）：页面里 `position: fixed` 的原点就是内容区左上角。
- 窗口拖动/缩放时**只推几何、不重传图**（`clipHistoryBackdropGeom`）：图不被重采样，全程清晰，拖动也不会一顿一顿地跳。
- 整屏只传一次，**JPEG(q88) 约 50KB**，比「裁出面板那块再传」的 PNG 还小，也省掉裁剪逻辑。实测整屏 JPEG 编码只要 7ms，而 PNG 要 100ms+。

### 3. 模糊与折射都在同一条 SVG 滤镜里做，模糊在前

```
feGaussianBlur → feImage(位移贴图) → 3×feDisplacementMap → 3×feColorMatrix → 2×feComposite
```

- **模糊放在滤镜里、不给 `.lg-desk` 加 `filter: blur()`**：CSS 的 `filter` 在元素边界外按**透明**处理，面板贴着屏幕边时会出现一圈发虚的边；`backdrop-filter` 的采样在边界外是**钳制**的，不会。放进来之后还顺带解决了「折射强度为 0 时没有模糊」——滤镜链第一级永远是模糊，折射只是可选的后续几级。
- **模糊值取「样式 → 毛玻璃效果 → 模糊」的 35%、上限 12px**，不直接用那个值：那个 25px 会把面板糊成一片，糊到没有细节可弯，折射就白做了。
- **三通道色散**：三个 `feDisplacementMap` 用略有差异的位移量各弯一次，各自用 `feColorMatrix` 只留一个通道，再用 `feComposite operator="arithmetic" k2=1 k3=1` **相加**还原。相加而不是 `screen` 混合——每张图只有一个通道非零，相加才正好还原亮度。色散差值随位移量缩放，面板小的时候不至于糊成彩虹。

### 4. 只在面板隐藏时采集桌面

面板可见时截图必然把面板自己也拍进去，中间那块是**镜中镜**，会把面板画成自己的背景。

- 不做「低频重拍 + `setOpacity(0)` 规避」：`setOpacity(0)` 会闪，`hide() + 截屏 + show()` 会被 Windows 的还原动画搞坏。
- 面板隐藏时窗口根本不在合成结果里，**天然拍到干净桌面**。隐藏期间每秒刷一次，超过 120 秒不再刷（托盘常驻程序不该一直空转）。
- 显示面板之前若缓存超过 8 秒，抢拍一张——`desktopCapturer` 的抓帧发生在调用那一刻，这时窗口还没 `show`，拿到的是干净桌面。
- 代价：面板里看到的是「上一次隐藏时」的桌面快照。配合显示前抢拍，通常不到一秒旧。
- 因为可见时不采集，「只更新面板外那一圈」的方案整个不需要了，`ClipGeom` 里也就没有 `mode` 字段。

### 5. 折射只作用于边缘，正文区域完全不参与

- 位移贴图是**圆角矩形 SDF 的梯度**，按「离边缘多远」做 `smoothstep` 衰减，中心区域的中性值（128）让 `feDisplacementMap` 完全不动。所以卡片文字所在的中间区域一点不弯，可读性不受影响。
- **采样方向朝内**：`R = 128 - (gx/len)*f*127` 配合**正的** `scale`。朝内取样既躲开「取到页面外空白」的发虚边，也正是液态玻璃边缘那种「背景被压向边缘」的观感。
- 参数按面板尺寸缩放，不写死：带宽 `clamp(10, min(w,h) * 0.07, 30)` CSS px，最大位移取带宽的 0.7 倍。写死 96px 时位移比带宽还大，边缘会被拉成一片没有梯度的糊。
- **位移贴图必须用 Canvas 生成、以位图交给 `feImage`**：用 SVG data URI 的话，SVG 会被当成图片渲染，里面的 CSS 属性不参与求值，中心永远无法中和，整个元素会变成一团扭曲。

### 6. 前景光学层（方案 A）独立于背景

`.lg-rim`（1px 环形渐变，`mask-composite: exclude`）/ `.lg-spec`（跟随指针的 `radial-gradient` + `soft-light`）/ `.lg-grain`（内联 `feTurbulence` 噪点）/ `body.glass` 的内侧高光 / 卡片与工具条的玻璃化描边。

这一层**不依赖任何背景像素**，所以系统材质生效与否都一样好看——这也是「系统透明效果关着的时候面板仍然像玻璃」的原因。

### 7. 两个滑块，不是一个总开关

- `剪贴板历史.玻璃强度`（`--lg-i`）：前景光学层的强度，0 等于关闭。
- `剪贴板历史.折射强度`（`--lg-refract`）：背景被弯曲的程度，0 表示只模糊不折射。
- **两个都为 0 时主进程完全停止采集**，面板退回纯色玻璃，零额外开销。
- 改动走 `clipHistoryGlass` 这条轻量通道：只让面板重算外观，**不重列历史**。复用 `clipHistoryChange` 会在拖滑块时把整个列表重渲一遍。
- 「样式 → 毛玻璃效果 → 模糊 / 不透明度」也接进了这条通道（面板的模糊与色纱跟着变），面板不再需要重开页面才生效。

### 8. 可读性与降级

- `prefers-reduced-motion: reduce`：去掉入场动画，保留静态外观。
- `prefers-reduced-transparency: reduce`：隐藏反光与颗粒，色纱提到 94%。
- 两个滑块都归零 / 截图失败 / 系统不支持时，三层背景自动隐藏，退回改动前的纯色玻璃外观。

## Considered Options

- **继续用系统材质（方案 B）** —— 放弃：要求用户先打开系统开关才能看到效果，且只有「背景变糊」，没有折射与前景光学层。
- **纯 CSS 半透明冒充液态玻璃** —— 放弃：`backdrop-filter` 采样不到桌面，做不出真折射。
- **`setOpacity(0)` 规避自捕获** —— 放弃：会闪。
- **`hide()` + 截屏 + `show()`** —— 放弃：Windows 的还原动画会让它看起来像在闪。
- **可见时只更新面板外那一圈** —— 放弃：面板外的那圈桌面本来就不会透过面板看到（只有边缘折射会采样到一点点），收益接近零，却要引入「用上一帧的中心 + 这一帧的环」这套合成逻辑。
- **位移贴图用 SVG data URI + `feImage`** —— 放弃：SVG 被当图片渲染，CSS 属性不参与求值，中心永远无法中和。
- **只给一个总开关** —— 放弃：折射强度对观感的影响很大，不同人接受度不同，必须能单独调。
- **正文区域也参与折射** —— 放弃：会影响读字，且与「边缘才是玻璃」的物理直觉不符。

## Consequences

- 面板的玻璃外观**不再依赖系统设置**，也不再依赖 `backgroundMaterial`；`backgroundMaterial: "acrylic"` 保留着（材质不生效时是零成本的），但已经不是观感的来源。
- 面板里原有的 `backdrop-filter: var(--blur)` **第一次真的有东西可模糊**——因为背后从纯色变成了真实桌面图。
- 面板里看到的背景是**上一次隐藏时的桌面快照**，不是实时的。对剪贴板面板这种「打开就用、看完就收」的窗口，这个取舍可以接受。
- 多了一条每秒一次的截屏（仅面板隐藏时，且两个滑块非零），超时后自动停。
- **抓到一个从第一版就存在的 bug**：`feColorMatrix` 的通道隔离矩阵三行都写成 `1 0 0 0 0`，三个通道相加后 `R = G = B`，整张背景变成灰度图。均匀的桌面背景上看不出来，是注入合成图案做像素级对比时才暴露的。
- **抓到另一个平台坑**：窗口最小化时 `getBounds()` / `getContentBounds()` 返回的是 -32000 那一带的哨兵坐标，拿它算偏移会把桌面图甩到屏幕外（实测 `left/top` 变成 21333px）。而采集恰恰几乎都发生在面板最小化的时候。修法是加一层采集上下文缓存：窗口正常时刷新，最小化时沿用上一次的值。

## 验证记录（探针实测）

| 项目 | 结果 |
| --- | --- |
| 背景图与真实桌面的像素对齐 | 误差 ≤ 1 设备像素（0.67 CSS px） |
| 镜中镜 | 已消除 |
| 折射作用范围 | 只落在边缘约 28 CSS px 的带内，中间完全不动 |
| 三通道色散 | 颜色正确，无色偏/灰度化 |
| 两个滑块为 0 | 背景层 `display: none`、主进程停采集 |
| 边界发虚 | 无 |
| 整屏采集 + JPEG 编码 | 约 130~180ms 采集 + 7ms 编码 |
