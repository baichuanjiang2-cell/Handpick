# 剪贴板面板的交付形态与交互细化

> 承接 [ADR 0004](0004-clipboard-history-standalone-window.md)。0004 解决了「点任务栏打开的是什么」，本决定解决「怎么交付给用户用」以及面板本身的五处交互细节。

## 背景

ADR 0004 之后功能已经跑通，但只在本机的开发环境里（`pnpm run start`）。要继续推进，先要回答两件事：

1. **怎么把它交到手上用**——每次开命令行跑 Electron 显然不是使用方式。
2. **面板还有几处粗糙的地方**——在真机上点过之后暴露出来的：窗口位置不记忆、置顶行为没定义、类型没法筛选、图片搜不到、以及一个潜在的「更新覆盖」隐患。

## 决定

### 1. 交付形态：免安装目录，沿用上游打包配置

不新增打包配置，直接复用 `package.json` 现有的 `pack` 脚本：

```
pack: npm run build && electron-builder --dir -c electron-builder.config.js
```

`--dir` 表示**只产出未打包的应用目录**，落在 `directories.output`（`build/`）：

- **`build/win-unpacked/e-search.exe`** —— 免安装，双击即用，整个文件夹可拷贝移动

注意 `electron-builder.config.js` 里 `win.target` 虽然写着 `nsis` + `zip`，但 **`--dir` 会忽略 target**，所以 `pnpm run pack` **不会**生成安装包和 zip。想要那两个产物得用 `dist` 脚本（`electron-builder -p never`，去掉 `--dir`）——**本分支不需要**，用户明确选了免安装形态。

打包所需的 5 个外部资源（PPOCR 模型 ×2、分割模型、`copy.exe`、`ffmpeg.exe`）已预先下载到仓库内，`beforePack` 会跳过下载。这些路径都在 `.gitignore` 里，不进版本库。

**GitHub 直连可用，不需要配镜像**——实测 `curl -sL` 拉 `ctrlc` release 返回 HTTP 200、147968 字节、1 次重定向。`electron-builder.config.js:93` 那行被注释掉的 `gh-proxy.com` 镜像**不要启用**。

### 2. 类型筛选：三个可多选的按钮，不持久化

工具条加三个按钮（只看文本 / 只看图片 / 只看文件），可多选，**都不选 = 全部**。

- 状态存在渲染进程的内存 `Set` 里，**不写进 store**：筛选是「这次想找什么」的临时查看动作，不是配置。
- 之所以需要它，是因为**图片条目没有文字可搜**，搜索框对它天然无效——图片只能靠类型筛出来。
- 搜索框与类型筛选**叠加生效**（先按类型过滤，再按关键词过滤）。

### 3. 位置记忆：记录坐标，并在越界时回退

面板的坐标与尺寸一起记进 `剪贴板历史.窗口位置` / `剪贴板历史.窗口大小`，复用 ADR 0004 已建立的滞回阈值 `WIN_SIZE_EPS`，避免坐标也跟着漂移。

回退规则：启动时若记录的坐标**完全不落在任何显示器的工作区内**（换了显示器、拔了外接屏、改了分辨率），就忽略它，改用系统默认位置。否则窗口唤出来在屏幕外，等于打不开。

`[-1, -1]` 是「还没记录过位置」的哨兵值（`defaultSetting` 的初值），**必须显式排掉**——它不是「左上角」。这一条是实机探针发现的：漏掉判断时首次启动面板会贴在屏幕左上角。

### 4. 置顶：面板默认置顶，但主搜索窗口出现时让出

面板是随手唤出的查看工具，**默认 `alwaysOnTop: true`**，否则一碰别的窗口就被盖住。

但永久置顶会盖住 OCR / 搜索 / 翻译的结果窗口，所以加一层协调（`syncClipHistoryTop()`）：**主搜索窗口存在时面板让出置顶，主窗口关闭后收回**。触发点有四个——面板创建、面板唤出、主窗口创建、主窗口销毁。

注意这是单向的：**主搜索窗口自己不置顶**（用户明确要求），面板也不跟着它置顶，只是「不挡它」。

### 5. 关掉自动更新检查：默认频率改为 `manual`

`main.ts` 的 `checkUpdate()` 拉的是**上游** release，用户点「更新」会 `shell.openExternal` 打开**上游官方安装包**。而本分支版本号仍是 `15.6.0`，与上游同名同版本——上游一发新版，界面就会提示「有新版本」，用户点下去会用上游版**覆盖掉定制版**，剪贴板历史这些改动全部消失。

因此 `defaultSetting.更新.频率` 从 `"start"` 改为 `"manual"`：不再自动检查，保留手动触发的入口。用户本机的 `config.json` 已同步改为 `manual`。

## Considered Options

- **自己写打包配置（绿色单文件 portable）** —— 放弃：electron-builder 的 `portable` 目标会把整个应用解压到临时目录再运行，启动明显变慢，且剪贴板历史要频繁读写用户数据目录，没必要为此牺牲启动速度。现有的 `win-unpacked` 已经是免安装形态。
- **把类型筛选做成下拉单选** —— 放弃：多选更贴近实际用法（「文本或图片，但不要文件」是很自然的诉求），且三个按钮的点击成本低于下拉展开。
- **筛选状态持久化** —— 放弃：会让「为什么我的列表是空的」变成一个难以自查的状态。每次打开回到「全部」更可预期。
- **面板始终置顶、不理会主窗口** —— 放弃：会盖住 OCR 和搜索结果，等于用一个小工具废掉主功能。
- **改掉版本号以避免更新误判** —— 放弃：版本号牵扯 `设置版本`、迁移逻辑与 `package.json`，改动面比「关掉自动检查」大得多，而收益相同。

## Consequences

- 用户拿到 `build/win-unpacked/` 即可直接双击使用，数据沿用 `%APPDATA%\eSearch`（配置、剪贴板历史、加密密钥全部继承）。
- 面板关掉再开，位置与尺寸保持不变；换显示器后不会跑到屏幕外。
- 面板不会挡住 OCR / 搜索 / 翻译结果窗口。
- 图片条目可以通过「只看图片」找到，不再有「搜不到」的死角。
- **代价**：不会再自动提示上游新版本。想升级定制版需要手动同步上游代码后重新打包。

## 未做

- **面板与主窗口的层级只做了「置顶 / 不置顶」两档**，没有做「面板失焦自动收起」。后者更接近专业剪贴板工具的手感，但需要处理失焦与托盘点击的竞争，留作后续可选。
- **打包未能在此环境完成验证**：`pnpm run pack` 在沙箱里会调用 `wmic.exe`（安全策略黑名单）并被拒绝批量清理产物目录，所以打包必须由用户在本机执行。代码层面的验证（lint / 类型检查 / 构建）已全部通过。
