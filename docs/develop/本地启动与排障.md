# 本地启动与排障

面向「从源码把软件跑起来」的人。前置准备（Node / pnpm / 镜像源）见[开始](start.md)。

> `pnpm run start` 是 `electron-vite preview`：**每次都会先构建一遍**，构建完才启动 Electron。它不是「直接打开已有产物」。

## 正常流程

```bash
pnpm install          # 必须完整执行安装脚本
pnpm run start        # 构建 + 启动预览
```

只看构建产物、不启动：

```bash
pnpm run build
```

常用检查：

```bash
pnpm run format       # biome format --write src/
pnpm run typecheck    # tsc -b --noEmit --force
pnpm run lint         # biome check src/
```

## 报错一：`Error: Electron uninstall`

**现象**：`pnpm run start` 构建成功，随后在 `getElectronPath` 抛 `Electron uninstall`。

**原因**：装依赖时用了 `pnpm install --ignore-scripts`（或安装脚本被中断 / 被安全软件拦掉），Electron 的 npm 包在、但真正的可执行程序没下载下来。判据：

```bash
ls node_modules/electron/path.txt           # 不存在
ls node_modules/electron/dist/electron.exe  # 不存在
```

`electron-vite` 只靠 `path.txt` 找 exe，缺一个就报这个错（见 `node_modules/electron-vite/dist/chunks/lib-ClgyQuZx.js` 的 `getElectronPath`）。

**修复（推荐）**：

```bash
pnpm rebuild electron
# 或
node node_modules/electron/install.js
```

**离线修复**：Windows 缓存一般在 `%LOCALAPPDATA%/electron/Cache/<hash>/electron-v<版本>-win32-x64.zip`。先核对 `node_modules/electron/checksums.json` 里同名包的 sha256，再把 zip 解压到 `node_modules/electron/dist/`，最后写 `node_modules/electron/path.txt`（内容就是 `electron.exe`，无换行）。`install.js` 在受限环境里可能因解压器的原生模块被终止，手工解压是等效的。

验证：

```bash
node -p "require('electron')"     # 应打印 dist/electron.exe 的绝对路径
```

**预防**：不要给 `pnpm install` 加 `--ignore-scripts`。

## 报错二：`A JavaScript error occurred in the main process` → `非法的翻译资源文件名: ./ignore.json`

**现象**：软件弹出错误框，栈指向 `out/main/main.js` 的 `readJson`。

**原因**：`lib/translate/translate.ts` 的 `readJson(name)` 用「只允许纯文件名」的正则校验**整个** `name`，但模块顶层就调用 `readJson("./ignore.json")`（另有 `./source.json`、`` `./${language}.json` ``），斜杠一定不匹配。这是仓库原有的缺陷，只要主进程真正启动就会触发。

**修复（已合入本分支）**：先取文件名再校验、再读取，原安全限制不变：

```ts
function readJson(name: string) {
    const base = path.basename(name);
    if (!/^[A-Za-z0-9._-]+$/.test(base)) {
        throw new Error(`非法的翻译资源文件名: ${name}`);
    }
    return JSON.parse(fs.readFileSync(path.join(rootDir, base), "utf8"));
}
```

改完必须重新 `pnpm run build`，因为报错发生在 `out/main/main.js` 里。

## 环境与工具注意

- **`ELECTRON_RUN_AS_NODE`**：某些 AI 辅助 / 自动化工具会设 `ELECTRON_RUN_AS_NODE=1`。带这个变量直接执行 `electron.exe` 会让它以 Node 模式运行，`require("electron")` 返回的是路径字符串，产生误导性的 `Cannot read properties of undefined (reading 'getPath')`。验证真实启动要清掉它：

  ```bash
  env -u ELECTRON_RUN_AS_NODE ./node_modules/electron/dist/electron.exe .
  ```

  正常启动会输出 `HandPick <版本> 启动` 并保持运行。

- **构建时清空产物**：build 会清空 `out/renderer/assets`。部分受限环境对「一次删除超过 50 个文件」有保护，会报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`。若遇到，先把 `out/renderer` 移到系统临时目录再跑 build，让它从零生成；普通终端没有此限制。
- **换行符**：仓库 `core.autocrlf=true`、文件是 CRLF，但 Biome 默认 LF。跑完 `pnpm run format` 后 `git status` 会多出若干「无内容 diff」的 M 条目，那是换行差异，不是代码改动。
- **第三方类型错误**：`pnpm run typecheck` 会报 `xtimelog` 的 `TS2532`，这是依赖自身的既有问题，与本仓库代码无关。要单独验证本仓库主进程侧代码：

  ```bash
  npx tsc -p tsconfig.node.json --noEmit --composite false
  ```

- `pnpm run dev` 目前跑不起来（带 `.node` 原生库的 vite 调试未配置好），用 `pnpm run start`。

## 启动后自检清单

```bash
# 1. 构建产物里没有录屏页面
find out -type f \( -iname "*record*" -o -iname "*videoEditor*" \)   # 应为空

# 2. 页面数量与 electron.vite.config.ts 的入口数一致
ls out/renderer/*.html

# 3. 主进程能正常起来
env -u ELECTRON_RUN_AS_NODE ./node_modules/electron/dist/electron.exe .
```
